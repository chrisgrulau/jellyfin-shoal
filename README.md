# Shoal plugin repository for Jellyfin

A [Jellyfin](https://jellyfin.org) plugin repository for the **Shoal** plugins, so Jellyfin can install and update them
from **Dashboard → Plugins**, with their icons and changelogs.

| Plugin | What it does |
| --- | --- |
| [Shoal Ingest](https://github.com/chrisgrulau/jellyfin-ingest) | Watches drop folders and files new media into your libraries, correctly named. |
| [Shoal Subtitles](https://github.com/chrisgrulau/jellyfin-subtitles) | Checks, synchronises and finds subtitles so they match the audio. |
| [Shoal AI](https://github.com/chrisgrulau/jellyfin-ai) | Shared AI provider settings and budgets for the other Shoal plugins (listed once it has a release). |

All of them are **alpha** and need Jellyfin **12.1** or newer.

## Adding the repository

1. In Jellyfin, open **Dashboard → Plugins → Repositories** (the gear or **Manage repositories**, depending on version).
2. Add a repository named `Shoal` with this URL:

   ```
   https://raw.githubusercontent.com/chrisgrulau/jellyfin-shoal/main/manifest.json
   ```

3. The plugins appear under **Catalog**. Install one, then restart Jellyfin.

A plugin you installed by hand is recognised as the same plugin: Jellyfin offers the repository's newer versions as
updates and, once one is installed, the manual copy is replaced.

## What is listed

[`manifest.json`](manifest.json) is generated by [`tools/update_manifest.py`](tools/update_manifest.py) from the plugins'
GitHub releases. A release is listed only when it is published, **immutable** and has a `SHA256SUMS` file. Its zip is
downloaded and checked against `SHA256SUMS` before the MD5 that Jellyfin verifies on install is written, and the version
in the plugin's `build.yaml` at that tag must match the tag. The releases also carry
[build provenance](https://docs.github.com/actions/security-for-github-actions/using-artifact-attestations), which you
can check yourself:

```
gh attestation verify jellyfin-plugin-ingest.zip --repo chrisgrulau/jellyfin-ingest
```

The **Check** workflow regenerates the manifest on every change and daily, and fails if `manifest.json` is out of date
(for example, a plugin has a new release that isn't listed yet).

## Updating

```
GITHUB_TOKEN=<optional token> tools/update_manifest.py
```

Needs Python 3.9+ and nothing else. Commit the new `manifest.json` in a pull request.
